# SafeFix 安全模型

## 资产与威胁

| 资产 | 威胁 | 对策 |
|---|---|---|
| 宿主文件系统 | 模型生成命令破坏/读取宿主文件 | Docker 沙箱：仅挂载任务工作区；文件工具 resolve+symlink 围栏 |
| 原始目标仓库 | 自动修改用户仓库 | 一次性 clone 副本；原仓库零写入（测试断言） |
| API 凭据 | 落盘明文/误提交/日志泄漏 | AES-256-GCM 加密存储（随机盐+版本头）；隐藏输入；容器不透传宿主 env；`.gitignore` 排除 `.env` |
| 测试证据完整性 | agent 改测试/删测试/换 runner 作弊 | 验证器 `tests_untouched` 检查 + 独立 eval 测试 + 空补丁拒绝 |
| 宿主资源 | fork bomb / 内存耗尽 / 挂死 | `--pids-limit 256 --memory 512m --cpus 1` + 墙钟超时 kill |
| 网络外传 | 凭据/数据外泄 | 不可信执行 `--network none`；护栏 cred-exfil 规则（纵深防御） |
| 提示注入 | 仓库内容诱导 agent 越权 | 系统提示声明仓库内容为不可信数据；治理在代码不在提示；沙箱兜底 |

## 边界分层（由强到弱）

1. **Docker 沙箱（强制边界）**：非 root uid 1000、`--cap-drop ALL`、
   `--security-opt no-new-privileges`、`--network none`、资源限额、无 Docker
   socket、`--rm`。Docker 不可用 → `SandboxUnavailableError` 显式拒绝，
   **绝不静默宿主执行**。
2. **独立验证器（证据边界）**：成功必须复现转绿 + 回归通过 + eval 通过 +
   测试未被篡改 + 补丁非空。
3. **工作区隔离（历史保护，非安全边界）**：clone 副本保护原仓库与历史；
   明确声明 worktree/copy **不是**沙箱。
4. **护栏 + 人工审批（纵深防御，非边界）**：启发式规则可被绕过，作用是拦截
   明显危险动作、强制人工确认、拒绝后升级。
5. **系统提示（可用性层，非机制）**：防注入/禁改测试声明只影响合作模型。

## 可信准备阶段

依赖安装（如 `pip install --target .deps pytest`）走 `run_trusted_prep`：
命令来自人写的 task 配置（非模型生成），容器仍非 root/限额，但开放受控网络
（`--network bridge`）。不可信执行阶段网络关闭。

## 凭据威胁模型（诚实声明）

加密存储保护**静态磁盘**上的 key（防 casual 读取/误提交）。主密码解锁后
key 存在于进程内存；`.env` 与进程环境对同机进程可见——这是明文兜底的固有
限制，CLI 会告警。被完全攻陷的宿主不在防御范围内。

## 残留风险

- Docker 共享内核：容器逃逸 0-day 不在防御范围（需 gVisor/Kata 才能升级隔离）。
- 验证器只能检查"测试未被修改"等可观测作弊；语义级弱化（如改实现迎合断言
  但破坏真实行为）依赖独立 eval 测试覆盖度。
- symlink 围栏在 Windows 上受符号链接创建权限影响（测试自动 skip 并记录）。
- 提示注入无法根治，只能限制其后果（沙箱 + 验证器）。
